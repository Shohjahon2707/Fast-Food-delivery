## Назначение

«Тёпло» объединяет меню ресторанов Ташкента, оформление заказа и его обработку. Покупатель может искать блюда самостоятельно или подобрать готовый обед по общему бюджету, числу человек, предпочтениям и времени доставки. Кухня получает заказ, а курьер и оператор работают с его статусами.

## Реализованные сценарии

| Сценарий | Результат |
|---|---|
| Найти ресторан или блюдо | Каталог показывает меню, цены и доступность. Ресторан со статусом «закрыт» можно посмотреть в общем списке. |
| Подобрать обед | Сервер собирает набор из блюд одного ресторана. Он учитывает число порций, доставку, время, предпочтения и заявленные аллергены. |
| Собрать корзину | Гость добавляет блюда без входа. После входа корзина переносится в аккаунт. При конфликте пользователь выбирает, какую корзину сохранить. |
| Узнать цену доставки | Сервер проверяет часы, минимальную сумму и настроенный радиус. Доплата и ориентир времени зависят от расстояния по прямой. |
| Оформить заказ | Сервер проверяет актуальные цены, доступность и итог. Заказ привязан к покупателю, а повторная отправка той же формы возвращает существующий заказ. |
| Оплатить | Наличные доступны по умолчанию. Payme появляется при настройке веб-кассы. Оплата картой подтверждается запросом провайдера. |
| Обработать и доставить | Кухня видит очередь и обновляет готовность. Курьер принимает предложение и завершает доставку. Покупатель может видеть свежую позицию курьера во время доставки. Оператор обрабатывает обращения. |

## Программная архитектура

| Слой | Компоненты |
|---|---|
| Интерфейс | Django Templates, HTML, CSS, JavaScript. Leaflet для выбора точки на карте. |
| Каталог | `menu` хранит категории и блюда, строит каталог и наборы. |
| Корзина | `cart` хранит гостевые позиции в сессии Django и позиции покупателя в базе. |
| Оформление | `orders` считает доставку, фиксирует состав заказа и обрабатывает состояния. |
| Пользователи и доставка | `users` управляет входом и профилем. `courier` обслуживает курьерские смены и назначение. |
| Оплата | `payments` хранит платежи и идентификаторы транзакций Payme. |
| Развёртывание | Python 3.12, Django 5.2, SQLite для локального запуска, PostgreSQL для CI и серверного окружения, Gunicorn и WhiteNoise. |

Исходники и миграции хранятся в GitHub. GitHub Actions запускает проверки с SQLite и PostgreSQL. Формы защищены CSRF, доступ к заказам проверяется по владельцу и роли, а callback Payme проверяет данные веб-кассы через HTTP Basic по HTTPS.

## Установка и запуск

В Windows CMD из каталога проекта:

```cmd
python -m venv venv
venv\Scripts\activate.bat
pip install -r requirements.txt
python scripts/compile_translations.py
python manage.py migrate
python manage.py seed_marketplace
python manage.py runserver
```

Главная страница доступна по адресу [http://127.0.0.1:8000/](http://127.0.0.1:8000/). Для демонстрации откройте «Умный обед», укажите 60 000 сум, двух человек, «Без мяса» и до 40 минут. Набор из риса с нутом, салата и воды стоит 50 000 сум. С базовой доставкой итог составляет 60 000 сум.

## Доставка и оплата

В админке ресторана вводятся часы работы, минимум по сумме блюд, координаты и радиус. Два пустых поля расписания оставляют доступность под ручным переключателем. Базовая цена доставки действует на расстоянии до 2 км. За каждый километр сверх 2 км добавляется 1 500 сум с пропорциональным расчётом за часть километра. Доставка обнуляется, когда стоимость блюд достигает установленного порога.

Для проверки Payme требуются Merchant ID, ключ тестовой веб-кассы и публичный HTTPS адрес для `/payments/payme/callback/`. В веб-кассе задаётся поле счёта `order_id`. В окружении задаются `PAYME_MERCHANT_ID`, `PAYME_API_KEY`, при необходимости `PAYME_LOGIN` и `PAYME_SANDBOX=true`. Сумма передаётся в тийинах. До подтверждения заказа Payme он недоступен для приготовления.

## Границы версии

Отзывы, избранное, повтор заказа, модификаторы, промокоды, несколько сохранённых адресов, SMS и Telegram, кабинет партнёра, предзаказ и аналитика описаны в плане v2. Ускорение поиска, Click, Uzum и проверка Payme внешней песочницей также относятся к дальнейшей работе. Время доставки является оценкой по прямой и базовому времени ресторана. На локальной SQLite подбор обеда показал медиану 104 мс за пять запросов при синтетических данных из 10 000 блюд и 100 ресторанов. Производительность на сервере следует измерять отдельно.
